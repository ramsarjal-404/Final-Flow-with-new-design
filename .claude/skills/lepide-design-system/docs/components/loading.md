# Loading

## When to use
- `SkeletonRows`: a table whose rows are loading. `DataTable` already renders it when `loading` is set; use it directly only in hand-built `.lf-table` markup.
- `PageLoader`: a whole page or a large panel is loading and there is no layout to sketch yet (route change, first load).
- `ProgressBar`: a long task with known progress (upload, export, scan) — or `indeterminate` when the task is running but progress is unknown.

## When not to use
- A button that is waiting on its own action: use `Button loading`.
- Short waits under about 300 ms: show nothing.
- Loading content that has a known shape other than a table (cards, KPI tiles): use the `.lf-loading` / `.lf-sk` skeleton classes on the real markup.
- A result: once the load finishes, replace the loader with the content, an `EmptyState` or an error.

## Anatomy
**SkeletonRows** (`<tbody class="sk-rows">`)
1. `rows` rows (default 7) × `cols` cells (default 5). Cells are 56 px tall with 0 16 padding (20 px on the first cell) and a 1 px `--border-soft` bottom border — the same height as real rows.
2. Each cell holds a 10 px pill bar (`.b`) whose width varies between 40 % and 89 % by position, with a `shimmer` gradient sweep (`--surface-3` → `#f9fafb` → `--surface-3`, 1.1 s, infinite).

**PageLoader** (`.page-loader`)
1. Full-height grid, content centred, 12 px gap.
2. Spinner (`.spinner-lg`): 32 px ring, 2.5 px `--surface-3` border with a `--brand` top segment, spins every 0.8 s.
3. Optional caption (`text`): 500 13/18 `--ink-3`.

**ProgressBar** (`.progress`)
1. Flex row, 10 px gap, min-width 120.
2. Track (`.progress__track`): 8 px pill, `--surface-3`, fills the row.
3. Fill (`.progress__fill`): `--brand`, width = `value` % (clamped to 0–100), animates width over 0.8 s.
4. Value (`.progress__val`): rounded percentage, 600 12/16 `--ink-2`, tabular numbers, min-width 34, right-aligned. Hidden when `indeterminate`.

## Variants and sizes
| Variant | Change |
|---|---|
| `ProgressBar indeterminate` | Fill fixed at 30 % width, sweeps from left to right every 1.1 s; no value text; no `aria-valuenow` |

`SkeletonRows` takes `rows` and `cols`; match `cols` to the table's column count.

## States
None beyond the variants. Under `prefers-reduced-motion` the shimmer, spin and sweep animations run once for 1 ms and stop, so the indicators stay visible but still.

## Accessibility
- `SkeletonRows` is `aria-hidden="true"`. Announce loading elsewhere — for example a "Loading…" caption or count (DataTable shows "Loading…" in its title counter) — and set `aria-busy="true"` on the table region if needed.
- `PageLoader` has `role="status"`, so the `text` caption is announced. Always pass `text` ("Loading reports…"); without it the status region is empty.
- `ProgressBar` has `role="progressbar"`, `aria-valuemin="0"`, `aria-valuemax="100"` and `aria-valuenow` (omitted when indeterminate). Pass `label` — it becomes `aria-label` ("Uploading licence file").

## Do and don't
| Do | Don't |
|---|---|
| Skeleton rows in the real table, same column count | A spinner in the middle of an empty table |
| `PageLoader` with a short caption | A bare spinner with no text |
| `ProgressBar` with `label` and real progress values | A fake progress bar that jumps to 99 % |
| `indeterminate` when progress is unknown | A determinate bar stuck at 0 % |

## Example
```tsx
import { SkeletonRows, PageLoader, ProgressBar } from '@lepide/ds-react';

if (!report) return <PageLoader text="Loading report…" />;

<table className="lf-table">
  <thead>…</thead>
  {loading ? <SkeletonRows rows={5} cols={4} /> : <tbody>{rows}</tbody>}
</table>

<ProgressBar value={uploaded} label="Uploading licence file" />
<ProgressBar indeterminate label="Scanning file servers" />
```

Plain HTML (with `@lepide/ds-css`):
```html
<div class="progress" role="progressbar" aria-label="Exporting" aria-valuemin="0" aria-valuemax="100" aria-valuenow="42">
  <span class="progress__track"><span class="progress__fill" style="width:42%"></span></span>
  <span class="progress__val">42%</span>
</div>
```
