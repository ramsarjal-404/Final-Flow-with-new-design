# Vertical tabs

## When to use
- The section list inside a settings-style `Modal`, beside the content pane ("General · Schedule · Recipients · Permissions").
- Four or more sections whose labels are too long or too many for `Segmented`.

## When not to use
- Two to five short sibling views in a page: use `Segmented`.
- Page-level navigation or the settings page section nav: use the sidebar / settings nav.
- Ordered steps the user must complete in sequence: use `Steps` or `WizardCard`.

## Anatomy
1. Container: `<div class="tabs" role="tablist" aria-orientation="vertical">`, a flex column with a 2 px gap.
2. Item: a `<button>`, 40 px tall, padding 0 12, radius 14 (`--r-md`), 600 13/1 text in `--ink-3`, left-aligned, 10 px gap.
3. Optional leading icon (`icon`): the component passes size 15, and the CSS renders it at 16 × 16.
4. Current item: the selected finish — `--sel-fill`, white text, `--sel-shadow`.

Pair it with a content pane: `.tabs__pane` is a flex column with a 16 px gap that fades up when it mounts (give it a `key` per tab to replay the fade). Lay the two out side by side yourself, for example a grid with a 200 px first column.

## Variants and sizes
None.

At 620 px and below the list turns into a horizontal row that scrolls sideways (`overflow-x: auto`).

## States
| State | Change |
|---|---|
| Rest | `--ink-3` text, no fill |
| Hover | `--surface-2` fill, `--ink` text |
| Current | `aria-selected="true"`: `--sel-fill`, white text, `--sel-shadow` |
| Focus | 2 px brand outline (`--focus-outline`), offset 2 px |

## Accessibility
- An ARIA tablist (`role="tablist"`, `aria-orientation="vertical"`, named by `ariaLabel`): each item is `role="tab"` with `aria-selected`; only the current tab is in the tab order. ↑/↓ (and ←/→) select the previous/next tab, Home/End the first/last, and focus follows. Give the panel `role="tabpanel"` if you need the full pattern.
- `Tab` enters the list on the current tab and leaves it on the next control.
- Move focus or announce the change in the pane only if your content needs it; the component does not.

## Do and don't
| Do | Don't |
|---|---|
| Short noun labels: "Schedule", "Recipients" | Verbs or sentences as tab labels |
| Use icons on every item or on none | Mix items with and without icons |
| Keep the dialog's footer actions outside the pane | Put a save button inside each section |
| Use it inside dialogs and narrow side columns | Use it for top-level page navigation |

## Example
```tsx
import { Modal, VerticalTabs, TextField } from '@lepide/ds-react';

const [tab, setTab] = useState('general');

<Modal open={open} onClose={close} title="Report settings" icon="settings" size="lg" footer={footer}>
<div style={{ display: 'grid', gridTemplateColumns: '200px minmax(0, 1fr)', gap: 'var(--s5)' }}>
  <VerticalTabs
    ariaLabel="Report settings sections"
    value={tab}
    onChange={setTab}
    items={[
      { value: 'general', label: 'General', icon: 'settings' },
      { value: 'schedule', label: 'Schedule', icon: 'clock' },
      { value: 'recipients', label: 'Recipients', icon: 'users' },
    ]}
  />
  <div className="tabs__pane" key={tab}>
    {tab === 'general' && <TextField label="Report name" value={name} onChange={setName} />}
  </div>
</div>
</Modal>
```

Plain HTML (with `@lepide/ds-css`):
```html
<div class="tabs" role="tablist" aria-orientation="vertical" aria-label="Report settings sections">
  <button type="button" role="tab" aria-selected="true">General</button>
  <button type="button" role="tab" aria-selected="false" tabindex="-1">Schedule</button>
</div>
```
