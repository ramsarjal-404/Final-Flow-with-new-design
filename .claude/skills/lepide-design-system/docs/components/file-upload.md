# File upload

## When to use
- Importing one file in a dialog or wizard step: a CSV of users, a licence file, a certificate, a logo.
- When drag and drop from the desktop is useful, with click-to-browse as the fallback.

## When not to use
- Several files at once: `FileUpload` takes only the first file of a drop or selection.
- Entering a server path or URL: use `TextField`.
- A button-only "Import" action with no drop zone: use a `Button` that opens a hidden file input.

## Anatomy
Empty (no `file`):
1. Drop zone `.upload` (`role="button"`, `tabIndex=0`): centred column, 8 px gap, padding 24, radius 14 (`--r-md`), 1 px dashed `--border-2`, fill `--surface-2`.
2. Icon tile `.mhead__ic`, sized 40 × 40: radius 14, `--brand-50` fill, `--brand` upload icon, `--brand-100` inner hairline.
3. Label `<b>`: 600 13/18 `--ink`; default "Choose a file or drop it here".
4. Optional `rules` `<span>`: 500 12/16 `--ink-3` — accepted types and size limit.
5. Hidden `<input type="file">` with `accept`.

With a file (`file` set):
1. Card `.basecard`: flex, 12 px gap, padding 12 14, radius 14, `--surface-2`, 1 px `--border-soft`, fades up.
2. Icon `.basecard__ic`: 36 px, radius 11, white, `--brand` file icon, `--sh-xs`.
3. Text `.basecard__text`: file name 700 13.5/18 `--ink`; size in KB (one decimal) 500 12.5/17 `--ink-3`, shown when `file.size` is given.
4. Remove button (only with `onClear`): `.lf-btn.lf-btn--icon` with an × icon, `aria-label="Remove file"`.

## Variants and sizes
None. The drop zone fills its container's width.

## States
| State | Change |
|---|---|
| Hover | `--brand-50` fill, `--brand-300` border |
| Dragging a file over (`.is-drag`) | Same as hover |
| Focus (keyboard) | Global 2 px brand outline (`--focus-outline`), offset 2 px |
| File chosen | Drop zone is replaced by the file card |

There is no built-in error or progress state: validate in `onFile` and show the error with `Field` (`error`) or a banner.

## Accessibility
- The drop zone is focusable and opens the file dialog on click, Enter or Space.
- Its accessible name comes from its text (label and rules), so keep the label explicit: "Choose a CSV file or drop it here".
- `accept` only filters the browser's file dialog; dropped files are not filtered — check type and size in `onFile`.
- The file input is reset after each pick, so choosing the same file again fires `onFile` again.
- The remove button has the accessible name "Remove file".

## Do and don't
| Do | Don't |
|---|---|
| State accepted types and the size limit in `rules`: "CSV, up to 5 MB" | Leave the user to discover limits from an error |
| Validate in `onFile` and show a specific error under the field | Silently ignore a wrong file type |
| Pass `onClear` so the user can replace the file | Leave no way to undo a wrong pick |
| Show the file name and size once chosen | Show a generic "File uploaded" with no name |

## Example
```tsx
import { Field, FileUpload } from '@lepide/ds-react';

<Field label="User list" error={fileError}>
  <FileUpload accept=".csv" rules="CSV, up to 5 MB" label="Choose a CSV file or drop it here"
    file={file} onFile={(f) => (f.size > 5 * 1024 * 1024 ? setFileError('The file is larger than 5 MB.') : (setFileError(null), setFile(f)))}
    onClear={() => setFile(null)} />
</Field>
```

Plain HTML (with `@lepide/ds-css`):
```html
<div class="upload" role="button" tabindex="0">
  <span class="mhead__ic" style="width:40px;height:40px"><!-- upload icon --></span>
  <b>Choose a file or drop it here</b>
  <span>CSV, up to 5 MB</span>
  <input type="file" accept=".csv">
</div>
```
