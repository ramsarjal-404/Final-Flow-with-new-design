# Chip

## When to use
- `Chip`: a short, read-only label on an object — a type, a category, a role, "Beta", "AI", a licence state next to a title.
- `ToneTag`: the status of a record in a table or detail panel ("Enabled", "Failed", "Pending"). Use `toneFor(status)` to pick the tone from the status word.
- `Counter`: a number beside a toolbar or section title ("Showing 1,204 events").

## When not to use
- Anything clickable: chips are `<span>` elements with no interaction. Use `Button`, `Segmented`, or filter chips (`.fchip`) above report tables.
- Removable filter values: use the report filter chips, not `Chip`.
- Long text: chips do not wrap (`white-space: nowrap`).
- Colour as decoration: tones are for status only.

## Anatomy
**Chip** (`.lf-chip`)
1. Pill, 22 px tall (`--chip-h`), padding 0 9, `--surface-3` fill, `--ink-2` text, 600 11.5/1 (`--type-chip`).
2. Optional leading icon (`icon`), 12 px, stroke 2, 5 px gap.
3. Label.

**ToneTag** (`.fx-op`)
1. Pill, 24 px tall (`--tone-tag-h`), padding 0 10 0 8, 600 11.5/1.
2. A 6 px dot in `currentColor` (a `::before`), 6 px gap.
3. Status text.

**Counter** (`.count-chip`): pill, padding 5 9, `--surface-3` fill, 600 11.5/1 `--ink-3` text.

## Variants and sizes
`Chip` tones:

| Tone | Look | Use |
|---|---|---|
| `neutral` (default) | `--surface-3`, `--ink-2` | Plain labels |
| `brand` | `--brand-50`, `--brand` text, 1 px inset `--brand-100` ring | Highlighted labels (AI, new, current) |
| `good` | `--success-bg`, `--success-text` | Positive state |
| `warn` | `--warning-bg`, `--warning-text` | Needs attention |
| `bad` | `--danger-bg`, `--danger-text` | Error, failure, risk |
| `flat` | `--surface-3`, `--ink-3` | Low-emphasis labels |

`ToneTag` tones: `good`, `warn`, `bad` (same fills and text as the chip tones), `info` (`--brand-50`, `--brand`), `none` (default: `--surface-3`, `--ink-3`).

`toneFor(status)` returns `bad` for words like failed, error, disabled, stopped, expired, denied, offline, critical; `warn` for warning, pending, queued, paused, partial, degraded, waiting, not configured; `info` for running, in progress, indexing, scanning, installing, updating; `good` for enabled, active, success, completed, online, connected, healthy, licensed; otherwise `none`. The checks run in that order, so "Running" maps to `info`.

One size each. Inside tables a chip truncates with an ellipsis; inside KPI cards it is 24 px tall.

## States
None. Chips, tone tags and counters are static.

## Accessibility
- They render plain `<span>`s; their text is read inline with the surrounding content.
- `ToneTag` never relies on colour: the status word is always shown next to the dot. Pass the full word ("Failed"), not a code.
- `Chip` accepts `title` for a native tooltip with the full text; do not put essential information only there.
- Tone text uses the `-text` colours, which meet 4.5:1 on their backgrounds.
- `Counter` shows a bare number; make sure the nearby label says what is counted.

## Do and don't
| Do | Don't |
|---|---|
| `ToneTag` with `toneFor(row.status)` for status columns | A coloured chip with no status word |
| One or two words, sentence case | Sentences or Title Case Labels |
| `brand` chips sparingly, for one highlighted label | Brand chips on every row |
| Use filter chips or buttons for anything clickable | Attach `onClick` to a chip |

## Example
```tsx
import { Chip, ToneTag, Counter, toneFor } from '@lepide/ds-react';

<h3 className="lf-card__title">
  File server audit <Chip tone="brand" icon="sparkles">AI</Chip>
</h3>

<ToneTag tone={toneFor(agent.status)}>{agent.status}</ToneTag>
<ToneTag tone="warn">Pending approval</ToneTag>

<span className="row">Events <Counter>1,204</Counter></span>
```

Plain HTML (with `@lepide/ds-css`):
```html
<span class="lf-chip lf-chip--good">Licensed</span>
<span class="fx-op fx-op--bad">Failed</span>
<span class="count-chip">1,204</span>
```
