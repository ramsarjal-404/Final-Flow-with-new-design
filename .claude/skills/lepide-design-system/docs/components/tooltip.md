# Tooltip

## When to use
- Name an icon-only control: every `IconButton` (`.lf-btn--icon`) already gets its `label` as a tooltip, with no extra code.
- Give a short hint on any other element: add `data-tip="…"` (e.g. a truncated name, a status icon, a disabled reason on a wrapper).

## When not to use
- Information the user needs to complete a task: put it on the page (help text under a field, a `Banner`).
- Rich content, links or buttons: a tooltip is plain text, one line, and can't be hovered or clicked. Use a `Menu` or a popover.
- Touch-only interfaces: tooltips need hover or keyboard focus.
- Repeating a visible text label.

## Anatomy
Mount `<TooltipHost />` once, near the root (next to `ToastProvider`). It renders one `<div class="tipfloat" role="tooltip">` and listens on the document; no wrapper component is needed per element.

What shows a tooltip — the nearest ancestor of the hovered or focused element that matches:
1. `[data-tip]` — text is the `data-tip` value.
2. `.lf-btn--icon` (`IconButton`, the × in modals and drawers, icon buttons in DataTable row actions) or `.dock-toggle` — text is the `aria-label`.

`data-tip` wins over `aria-label` when both are present. Elements with neither show nothing.

Bubble `.tipfloat`: fixed, z-index 120 (`--z-tooltip`), ink fill (`--ink`), white 600 12/16 text, padding 6 10, radius 8 (`--r-xs`), one line (`white-space: nowrap`), `pointer-events: none`.

Placement: centred 8 px above the element; below it when there is less than 8 px of room above; kept 8 px inside the window edges. Inside the side dock (`.lf-dock`) it sits 10 px to the right of the element, vertically centred.

## Variants and sizes
None.

## States
| State | Behaviour |
|---|---|
| Hover | Appears after 350 ms over the same element; fades in with a 2 px rise over 150 ms (`--t-fast`) |
| Keyboard focus | Appears immediately when the element receives `:focus-visible` (not on mouse focus) |
| Hide | On mouse leaving to a non-tip element, focus out, any mouse press, Escape, any scroll (including inner scroll containers) and window resize |

## Accessibility
- The tooltip is decorative support: the accessible name comes from the element's own `aria-label` (an `IconButton` `label` is required for this reason). Don't rely on `data-tip` as the only name of an icon-only control — give it an `aria-label` too.
- It appears on keyboard focus as well as hover, and Escape hides it.
- The bubble has `role="tooltip"` but is not linked with `aria-describedby`; screen readers read the element's label, not the bubble.
- Keep the text short (a few words); it never wraps.

## Do and don't
| Do | Don't |
|---|---|
| Mount `<TooltipHost />` once per app | One `TooltipHost` per page or per component |
| `IconButton label="Refresh"` and let the tooltip follow | Add `data-tip` that repeats the same label |
| `data-tip` for short hints: "Read-only — managed by policy" | Sentences, instructions, or anything with a link |
| Sentence case, no trailing full stop | Title Case Tooltips. |

## Example
```tsx
import { ToastProvider, TooltipHost, IconButton, Icon } from '@lepide/ds-react';

// Once, at the root:
<ToastProvider>
  <App />
  <TooltipHost />
</ToastProvider>

// Anywhere below:
<IconButton icon="refresh" label="Refresh" onClick={reload} />          {/* tooltip: "Refresh" */}
<span data-tip="Synced 4 minutes ago" tabIndex={0}><Icon name="clock" /></span>
```

Plain HTML (with `@lepide/ds-css`, `TooltipHost` mounted):
```html
<button type="button" class="lf-btn lf-btn--icon" aria-label="Delete">…</button>
<span data-tip="Managed by policy" tabindex="0">…</span>
```
